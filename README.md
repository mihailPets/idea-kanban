# Канбан-доска Idea Platform

Канбан-доска для тестового задания Idea Platform. Четыре колонки, поиск по описанию и датам, редактирование, удаление и перенос задач. Новые задачи создаются в To Do.

[Открыть публичное демо](https://mihailpets.github.io/idea-kanban/)

## Запуск и проверки

```sh
nvm install
npm ci
npm run start
npm run check
```

Сервер разработки доступен на [127.0.0.1:8080](http://127.0.0.1:8080/). Для воспроизведения задания используется Node.js **18.18.0**. Ветка Node.js 18 снята с поддержки. `npm run check` последовательно запускает lint, typecheck, тесты и production build.

Тест просрочки находится в [src/board/rules.test.ts](src/board/rules.test.ts) и запускается через `npm run test`. Тот же набор покрывает операции над задачами и восстановление из хранилища. CI запускает его в UTC и America/New_York.

Браузерные тесты в [tests/board.spec.ts](tests/board.spec.ts) проверяют сохранность черновика при активном поиске, валидацию формы и обозначение просрочки. Для локального запуска установите Chromium командой `npx playwright install chromium`, затем выполните `npm run test:browser`. CI запускает этот набор перед публикацией.

## Руководство для ревьюера

- [Board.tsx](src/board/Board.tsx) связывает интерфейс, поиск, датчики переноса и управление фокусом. Для переноса с клавиатуры сфокусируйте ручку карточки, нажмите пробел, выберите колонку стрелками и подтвердите пробелом. Escape отменяет перенос.
- При открытой форме поле поиска доступно только для чтения. Текущий фильтр сохраняется, чтобы карточка и её черновик оставались на доске до сохранения или отмены.
- [useTasks.ts](src/board/useTasks.ts) владеет списком. Правила в [tasks.ts](src/board/tasks.ts) и [calendar.ts](src/board/calendar.ts) не зависят от React, а [storage.ts](src/board/storage.ts) проверяет сохранённые данные до передачи в приложение.
- [Спецификация OpenSpec](openspec/changes/add-kanban-board/specs/kanban-board/spec.md) описывает ожидаемое поведение. [ADR](openspec/changes/add-kanban-board/design.md) объясняют выбор единого списка, календарной логики и сортировки после переноса.

Изменения хранятся в текущем браузере. Вкладки не синхронизируются. При недоступности сохранения изменения действуют до перезагрузки. Порядок карточек задаётся датой начала, а даты отображаются в часовом поясе браузера. В исходном JSON дедлайны в прошлом, поэтому при первом запуске 12 задач вне Done отмечены как просроченные.

Публикуется статическая сборка. При проверке `npm audit --omit=dev` у зависимостей приложения не было известных уязвимостей. Полный `npm audit` сообщил о замечаниях в инструментах разработки.
